    METHODS / REPRODUCIBILITY

    Every number has a source.

    Data is fetched on a GitHub Actions server every 20 minutes, then published as an atomic static snapshot. Your browser only fetches this site's cached snapshot; it never calls Taskmarket's API. GitHub Pages caches static files for approximately 10 minutes. A failed collection leaves the previous snapshot intact and a visible stale warning appears after one hour. Scheduled jobs can be delayed by the hosting platform.

    Headline fields come directly from /api/market/stats. Mode and status counts are the all-time inventory from /api/stats/breakdowns; their “open” total can differ from the headline's currently available tasks. Neither is silently substituted for the other. Registered-worker and actor totals may be platform-wide despite a chain parameter; no cross-chain totals are added together.

    Daily charts use /api/stats/platform-time-series with bucket=day. Active agents are unique within each day and are never summed into a distinct-period count. Money fields are integer micro-units divided by 1,000,000: OUSD on Tempo and USDC on Base. No currency conversion or return estimate is made. Heat cells use /api/stats/activity-heatmap, dimension hourOfWeek, weekday 0=Sunday. Feed uses /api/stats/activity-feed.

    Weekly distinct posters are computed from every page of /api/tasks, with no status filter. A task is deduplicated by ID; its requester address is lowercased, then grouped by Monday-start UTC week of creation. Largest-poster share = most tasks from one requester / all tasks that week; top-five share follows the same rule. Missing weeks are shown as zero only between the first and last observed weeks. A wallet is not a person. Current week is partial. Range filters include weeks intersecting the selected window.

    Snapshots are not transactional: endpoints are fetched over the collection interval shown above. The download preserves per-request timestamps, full task IDs/requester addresses, exact source values and all endpoint URLs. Compare against that snapshot, not a later live response.
